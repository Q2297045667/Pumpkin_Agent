# Pumpkin 插件迁移指南

本仓库为服主、插件维护者和编程 Agent 提供一份协作指南，用于把现有 Minecraft 插件迁移到 Pumpkin。服主可以用它说明哪些玩法和旧数据必须保留，开发者可以据此选择插件接口迁移插件，完整约定位于 [AGENTS.md](./AGENTS.md)。

## 如何开始

Fork（方便上游更新）一份让 Agent 能够读取本仓库的 `AGENTS.md`、原插件源码和目标 Pumpkin 源码。发起任务时，给出原插件版本、目标 Pumpkin 版本或提交，以及玩家最常用的操作。如果已有存档，附上旧插件生成的配置和脱敏数据样本，并说明切换后旧服是否还要读写同一份数据。

Rust 插件使用 `wasm32-wasip3` 和 Pumpkin Wasm API 0.2 时，可以从 [GitHub Actions 构建与发布模板](templates/wasm-plugin/README.md) 复制配置。模板提供拉取请求检查、自动 Nightly、手动 Releases 和可选的 Pumpkin Market 上传。

### 任务示例：迁移传送点插件

> 请按本仓库的 AGENTS.md，将〈原插件源码路径和版本〉迁移到〈Pumpkin 源码路径和提交〉。玩家需要能按原名称使用已有传送点，旧服也要能读取新服修改过的坐标。请先对照原插件列出命令、权限、数据格式和验收步骤，核对 Wasm 接口能否覆盖这些操作。若需要第三方插件，请说明用途、是否必需及缺失时的影响，由我确认后再采用。

## 迁移时要核对什么

| 环节 | 核对要点 |
| --- | --- |
| 原插件行为 | 确认插件运行在服务端、代理端还是两端。从命令、事件和存储追踪一次完整操作，包括权限不足、操作取消和失败后的状态。 |
| Pumpkin 接口 | 优先评估 Wasm。只有当 Wasm 无法实现大部分功能时才考虑 Native。选定接口后，先将原样模板构建并加载到目标服务端，记录 Pumpkin 提交、Minecraft 和 SDK 版本。 |
| 配置与数据 | 新配置使用 TOML。旧配置文件中的传送点、余额等也属于玩家数据。按原插件的存储格式和旧服读写需求，确定沿用原库还是一次性无损导入。 |
| 检查与回滚 | 在独立测试服分别验证全新安装和旧数据迁移。用原玩家身份读取一条旧记录，修改后重启，再次读取并核对结果。演练恢复备份，同时交代如何保留切换后新增的数据。 |

## 最后能够得到什么

- **给服主的安装入口**。在插件项目的 `README.md` 中写清支持的 Pumpkin 版本、Wasm 或 Native 产物、依赖、安装位置和首次启动步骤，并给出一个能当场确认加载成功的命令或游戏操作及其预期结果。
- **给玩家和管理员的使用说明**。在插件项目的 `doc/` 中列出命令、别名、权限、配置示例及生效方式。优先覆盖英语（`en_us`）和简体中文（`zh_cn`），用对应语言的客户端核对实际提示。
- **给维护者的迁移与验证记录**。记录备份、试迁移、切换和回滚步骤，列出功能差异、测试环境与实际结果。尚未实测的平台或行为标为“未验证”，并附可复现的检查步骤。

小型插件可以将上述内容合并到插件 README。迁移和回滚步骤较长时，可单列为 `MIGRATION.md`。
