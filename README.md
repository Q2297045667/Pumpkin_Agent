# Pumpkin 插件迁移指南

Pumpkin_Agent 给服主、插件维护者和编程 Agent 提供一套迁移约定，涵盖插件接口选择、旧数据兼容、客户端实测和发布。准备迁移已有的 Minecraft 插件时，从 [AGENTS.md](./AGENTS.md) 开始。已有 Rust Wasm 插件、只需接入构建与发布时，可直接使用[构建模板](templates/wasm-plugin/README.md)。

## 发起一次迁移

将本仓库、原插件源码和目标 Pumpkin 源码放在 Agent 能读取的位置。需要保留自己的迁移约定并跟进上游更新时，可以先 Fork 本仓库。发起任务时，下面几项信息能帮助开发者判断要保留哪些行为，以及怎样验收。

| 提供什么 | 具体到什么程度 |
| --- | --- |
| 原插件与目标版本 | 原插件的源码路径或仓库、版本、运行平台，以及目标 Pumpkin 的版本或提交。 |
| 玩家依赖的操作 | 给出一条实际命令或一次完整操作，说明成功、无权限及操作取消时玩家会看到什么。 |
| 旧数据与部署方式 | 提供旧插件生成的配置、脱敏数据样本和数据库类型。说明切换后是否还要让旧服读取新数据，是否有多台服务器同时写入。原插件自带 Web UI 时，注明需要保留的页面操作。 |
| 本地测试环境 | 提供已有的 Pumpkin 测试服目录、版本和已启用的插件 API。原插件在 Paper 上运行时，附上 Paper 测试服目录。需要 GUI、粒子或声音时，再提供客户端位置及要验证的版本。 |

### 可直接使用的提示词

> 请按本仓库的 AGENTS.md，将〈原插件路径及版本〉迁移到〈目标 Pumpkin 版本〉。本地测试服位于〈Paper 目录〉和〈Pumpkin 目录〉，Pumpkin 已启用〈插件 API 版本〉,需要兼容〈数据库〉。
>
> 请先核对命令、权限和数据格式，再评估 Wasm 能否覆盖这些操作。若需要第三方插件，请说明用途、是否必需及缺失时的影响，由我确认后再采用。

## 如何检查

- **功能与接口。** 优先评估 Wasm，Rust 插件优先考虑 `wasm32-wasip3`。先让目标服务端加载原样模板，再迁入业务代码。只有 Wasm 无法实现大部分功能时才考虑 Native。按原插件的结果逐项核对命令、权限、取消和失败路径。

- **配置与存档。** 新配置使用语言自带支持（如 Rust 可使用 TOML），旧配置文件也要迁移。沿用原库时，用旧插件读回新插件修改过的数据。一次性导入时验证重试不会重复创建记录，并演练如何恢复备份、处理切换后新增的数据。

- **安装与使用。** 迁移后，插件 README 应给出支持版本、依赖、安装位置和一个能验证安装成功的操作。详细命令、权限和配置写在插件项目的 `doc/`。分别在全新安装和旧数据迁移后验证主要操作，用英语和简体中文客户端核对提示。记录实测结果和已知差异，未验证的功能附上可复现的步骤。

## 构建与发布

仓库提供面向 Rust `wasm32-wasip3` 和 Pumpkin Wasm API `0.2.0` 的 GitHub Actions 模板。接入后，拉取请求运行构建检查，每次分支推送以最后一个提交生成 Nightly 预发布版。正式版由维护者在默认分支手动运行 `Releases` 发布。需要上传 Pumpkin Market 时，由维护者在该流程中明确勾选，上传使用对应 GitHub 正式版的原始附件。复制方法、本地构建命令和商店配置见[模板使用说明](templates/wasm-plugin/README.md)。
